# 本地部署的可行性

小型实验室如何实际部署推荐的第一阶段特征集。以范围综述目录 (`docs/scoping_review/`) 为基础，并与`IMPLEMENTATION_PLAN.md`中的提取器接口约定和`ANNOTATION_FORMAT.md`中的输出格式保持一致。设计锚点：本地优先、显式 `NaN` 空值、一个公共时间网格、可重现的出处。

## 1. 硬件层

四层，源自每个工具的目录可部署性标签 (`yes-cpu` / `yes-gpu` / `yes-heavy-gpu` / `api-only`) 并针对真实 VRAM 进行健全性检查：

- **A 层 — CPU 主干（无 GPU）。** 所有低层视觉和音频统计、词汇和句法规范以及事件分割算法：librosa、openSMILE、Praat/parselmouth、scikit-image/OpenCV、spaCy。可在任何笔记本电脑/服务器上运行。
- **B 层 — 单 24 GB GPU 主力。** SigLIP / DINOv2、SEA-RAFT（流）、Whisper (ASR)、BEATs（音频标记）、Qwen3-Embedding、RTMPose、Depth-Anything 和 7B VLM（4 位 Qwen2.5-VL-7B）。这一层涵盖了绝大多数高级功能。
- **C 级 — 48 GB+ GPU。** 较重的型号（InternVideo2、ViTPose-G、Q-Align、70B/72B LLM）。每个都与 B 级替代品配对，除非需要提高准确性，否则应首选该替代品。
- **D 层 — 仅 API（可选）。** 前沿嵌入和前沿多模式判断。不需要；每个都有一个本地默认值，并用作准确性上限/验证参照。

## 2. 环境与编排

部署的难点在于**各工具的依赖环境互不兼容**（TensorFlow、PyTorch、CTranslate2、mmcv，加上 MATLAB 来源SHINE/Rosenholtz 代码）。可按以下方式组织环境：

- **5–6 个锁定的 `uv`/conda 环境**，每个环境在统一的 `Extractor` 接口 (`src/nfe/base.py`) 后面都有一个常驻 GPU 工作线程。
- **Snakemake/Prefect DAG** 协调每个刺激的提取，并以 **转录本为中心** 排序（ASR 运行较早，因为语言/社交/情境模型消耗带时间戳的转录本）。
- **摄取细节：** 以约 2 fps 的帧采样加上每个镜头的关键帧；音频提取为 16 kHz（语音）和 44.1 kHz（音乐/原声）WAV。
- **每个模型系列的批处理规则**； **在阶段边界进行内容寻址缓存**，以实现幂等性和来源（缓存原始原始采样率输出，以便可以重新生成公共网格，而无需重新运行模型）。
- 一个**单个公共网格重采样器**，具有每个特征类型规则（连续/概率/分类/每个单词/稀疏事件），发出固定维度、`NaN`填充的输出（参见`ANNOTATION_FORMAT.md`§2.4）。

## 3. 运行时和存储

- 每小时刺激实时系数 (RTF)：**核心配置运行 ~0.5–1× 实时** — 一部 2 小时的电影在 A+B 层上过夜进行标注。
- 成本驱动因素：每镜头 VLM、密集每帧深度/显著性/分割、pymoten 运动能量和 benepar 选区解析。
- 存储预算：**每小时低几十 GB** 的刺激（以密集嵌入/矢量通道为主；HDF5 分块 + gzip 控制这一点）。

## 4. 受益于托管大型模型的功能

只有 **3–4** 类实际上可以从大型托管模型中获益，每个模型都有一个本地 `include` 默认值：

1. 高级**社会互动**语义/心理理论标记。
2. 转录级**叙述/事件索引**情境标记。
3. **多模式影响**与基本原理。
4. （可选）高端**嵌入**。

接口指导：相同`Extractor`接口背后的瘦API客户端； JSON 模式验证的结构化输出；每个镜头/每个场景的粒度；批量+缓存+重试；选择加入`allow_hosted`隐私门；使用 API 主要是为了**验证/提取到本地 7-8B 模型**，而不是作为运行时依赖项。如果连接托管法官，请参阅 `claude-api` 技能参考，了解人择模型 ID、结构化输出和定价。

## 5. 推荐的默认配置

- **核心（零 API）：** 仅 A 层 + B 层。完全本地化，每部长片过夜，涵盖推荐的核心特征集。
- **扩展：** 添加 C 级模型，其中精度增益是合理的。
- **托管（选择加入）：** 为上述 3-4 类启用 D 级，由 `allow_hosted` 控制。
